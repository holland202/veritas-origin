# EXP003-P0 — Controlled hypothesis discrimination substrate

**Status: EXPLORATORY INTEGRATION PROTOCOL — NOT PREREGISTERED CONFIRMATORY; NOT VALIDATED**

## Research boundary
Can an external small-model proposer select valid, information-bearing experiments that reduce uncertainty over a fixed set of hypotheses under a constrained observation budget? The software supplies a task generator, policy baselines, a resource/proposal gate, an execution loop and raw-evidence persistence. **Without an external model configured and executed, it is not autonomous AI research.**

## Task generator and observable context
Each task seed deterministically selects four distinct named binary functions from a frozen registry of eight. One of the four is hidden truth, selected by a separate deterministic random stream. Probe domain: integers 0..31. The proposer sees candidate names, descriptions, past probe/outcome pairs, current step and remaining budget; it does **not** receive the truth label during action selection. The experiment's raw evidence includes truth for auditing and must not be supplied to the proposer. Observations are exact (no noise). A proposal must be a JSON object with precisely one key, `probe`, whose value is an integer in range not previously queried.

## Controls
- `fixed`: first unused integer in ascending order.
- `random`: unused integer drawn with per-seed deterministic RNG, separate from task construction.
- `greedy`: choose maximum expected eliminated hypotheses under a uniform posterior, tie-break lowest integer. This is the strong deterministic information-gain control.
- `external`: user-selected trusted command consumes a JSON observation via stdin and emits exactly `{"probe": integer}` to stdout. This adapter is **not a security sandbox**. It is not enabled by default. No cloud or proprietary inference is required by the substrate.

All policies share the same seed-specific task and maximum of six queries. Each exits early at a singleton candidate. Invalid external proposals, timeouts, and process failures cause `DEFERRED`, not a silent fallback. The model may propose; only the deterministic gate decides admissibility.

## Recorded outcomes / descriptive pilot endpoints
Per seed/policy: full pre/post candidate sets, selected probe, observed outcome, remaining set, hidden truth, solved flag, and failure/defer state. Summaries: fraction solved within six probes, mean terminal number of hypotheses, number deferred. Results are **exploratory**, not hypothesis-confirming. Pilot seeds are explicitly configured (default 0..11); do not claim held-out generalization.

## Limits and pre-confirmatory work
The registry is synthetic, small, transparent, and solvable by a deterministic greedy baseline. The optimizer's formula is visible; model parity with greedy is not novelty. A confirmatory EXP003-C1 requires (before any confirmatory run): pinned model artifact SHA-256 and inference configuration, immutable task-generation code, preregistered held-out seeds, explicit improvement threshold relative to all controls including greedy, error/timeout handling, cost and token accounting, independent verifier, and evidence isolation. Preserve pilot failures and outputs as separate uniquely named JSON files. Never retroactively classify pilot results as confirmatory.

## Authorization and budgets
The CLI refuses execution without `--pilot`. Seeds are bounded to at most 100 per pilot call, six queries per policy per seed, external subprocess timeout <= 60 seconds per proposal. The external binary runs with privileges of the invoking user and may itself access other resources: run only approved local binaries or install an actual sandbox before untrusted models/tools. There is no automatic ability to modify research code, authorize itself, deploy software, or change evaluation rules.

## Evidence semantics
`EXPLORATORY_SIMULATED` means synthetic observations generated by fixed code. A digest or successful replay shows byte integrity/consistency, not empirical truth. This prototype is not a validated autonomous scientist.
