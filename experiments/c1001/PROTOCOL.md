# C1-001 — Linux discretionary-access-control evaluator boundary: prospective protocol

**PREREGISTERED BEFORE C1-001 CODE, TESTS OR OUTCOMES.**
**Scope:** A controlled, *real OS-user-separation* evaluation on a Linux GitHub-hosted runner; **NOT** a full sandbox, trustworthy general-purpose access monitor, third-party code containment, or a validated LLM test.

## Prior observations

- EXP003-P0 records that filtering a seed from the prompt is insufficient, and an ordinary local subprocess can read ambient host resources.
- EBA-001 ([protocol](../eba001/PROTOCOL.md), [report](../../reports/eba001/EBA001_RESULTS.md)) demonstrated a known **E9 false clean**: fake complete-clean access logs can fool a declared-provenance classifier despite a mathematically consistent trace. Preserve this as the precondition, not a repaired historical failure.
- RA-001 freezes original historical evidence and retains an unauthorized Sovereign Veritas publication intent by default. This project does **not** mint approval tokens or modify the Sovereign Veritas Gate.
- EACE and Veritas Evaluation Harness motivate real access boundary tests and detection of self-attested logs. No third-party code imported.

## Hypotheses and nulls

**H1 (constrained):** On the selected GitHub-hosted Linux runner, under different non-root Unix UIDs and correctly configured filesystem permissions, a known proposer script cannot read the evaluator's protected `0600` answer file, nor traverse the evaluator-only `0700` directory. Root/administrator/capabilities and vulnerabilities are out of scope.

**H2:** A separate Unix-domain evaluator will allow a context-only honest proposer to solve one fresh synthetic task through a bounded `HELLO` / `PROBE` protocol **without providing the true label, secret salt, private file path, or any raw private evaluator file bytes** to the proposer.

**H3:** A denied request for evaluator secrets and requests by an unauthorized peer UID are refused, without leaking an answer. A later valid, authenticated proposer session still succeeds (**non-vacuity**).

**H4:** A standalone, code-independent historical replayer can verify the evaluator-owned trace after post-session disclosure of the ground truth and random commitment salt, but its PASS does *not* certify the absence of every possible side channel or external attacker behavior.

**H5 (negative):** Without independently authenticated file/process/peer telemetry, an unsigned claim by the proposer that it never accessed hidden data must **not** be promoted to `ISOLATED`. Even in the correctly configured DAC fixture, overall system isolation is `PARTIAL_DAC_DEMONSTRATED`, not `SECURE_SANDBOX`.

## Frozen experiment design

- Linux x86-64 GitHub-hosted `ubuntu-24.04`, using root *only* to provision ephemeral Unix users and ACL-like owner/group permissions. Separate UIDs: evaluator `32001`, proposer `32002`, other-peer negative control `32004`, shared socket GID `32003`.
- Private directory owned by evaluator, mode `0700`; private answer + salt material stored only there, mode `0600`, generated by CSPRNG **after** CI starts. No secret in Git, command line flags, proposer environment, stdout, network, or public fixture.
- Public Unix-domain socket directory group `32003`, mode `0770`; socket group `32003`, mode `0660`; server obtains Linux peer credentials via `SO_PEERCRED` and accepts **only proposer UID 32002**. A peer of UID 32004 with the same socket group must fail authorization.
- Evaluator and proposer run in different **actual OS processes** with different UIDs. The evaluator reads a private task assigned from four named synthetic predicates and reveals to the proposer only candidate names and prior outcomes; the chosen answer and random nonce stay private until the evaluator exits. A fixed dictionary of public predicates and integer probe domain 0..31, six distinct probes max.
- Only declarative line-delimited JSON requests are accepted, with exact command schemas and hard length bounds. No arbitrary user code is run inside the evaluator; the CI-provided proposer is a small known test program. Not a general-purpose sandbox for hostile models.
- An honest proposer uses expected elimination (greedy), no oracle access, and must complete the task within the six-probe budget.
- Logging: evaluator alone writes an append-only-in-process event list and final read-only JSON receipt inside its private directory. After the server exits, CI root copies that *already written* receipt for a separate verifier; the proposer cannot edit it under tested file permissions. It is **not cryptographically signed**, and root can modify any evidence.
- Commitment to hidden assignment must be **salted** to defeat enumeration of the small predicate space: `SHA256(canonical({"trial_id","candidates","truth","salt"}))`, with 32 random bytes in the undisclosed salt. No public seed used to regenerate the private truth.
- Avoid using `/proc` as a security boundary; optionally test an ordinary other-UID read of the evaluator's `/proc/<pid>/environ` but document kernel-dependent proc visibility. The primary hard negative is private file traversal + authorization.

## Registered control matrix

| Control | Action and expected observable result |
|---|---|
| P0 | Valid same-UID proposer `HELLO` and legal `PROBE` exchange; eventually solves, independently replayed |
| N1 | Proposer UID directly opens protected private task file ⇒ Linux `EACCES` |
| N2 | Proposer UID traverses evaluator private directory ⇒ Linux `EACCES` |
| N3 | Same-UID proposer sends `GET_SECRET` or `READ_FILE` request ⇒ protocol denies, returns no secret |
| N4 | Other UID with socket group access connects ⇒ `SO_PEERCRED` rejects (even though group permits connection) |
| N5 | Duplicate, malformed, out-of-range, Boolean or non-integral probe ⇒ fails safely; valid subsequent probes continue |
| N6 | Caller tries to forge `approval`, `truth` or `source_revision` field ⇒ strict schema rejects |
| N7 | Receipt JSON has altered outcome, changed hidden answer or a rehashed mutation ⇒ standalone replayer fails |
| N8 | Receipt is absent, has duplicate JSON keys, nonfinite JSON number or secret commitment mismatch ⇒ fail |
| N9 | A perfect **self-attested** proposer access log, regardless of signatures absent external trusted identity ⇒ not upgraded to secure-isolation claim |
| N10 | Process ownership/sockets/private mode misconfigured ⇒ setup FAIL before the honest task, never silently skip |

An invalid input is different from an OS-denied access. The result ledger reports exactly which enforcement mechanism blocked a given case, and **does not call schema rejection an OS sandbox**.

## Primary metrics and stop rules

- Binary: honest session completes under budget; user-id separation validated using `os.geteuid` and server-side `SO_PEERCRED`.
- Count: `EACCES` private-file/directory attempts; prohibited socket/protocol calls; declared but untrusted access-log outcomes; independent replay passes.
- One fresh hidden task per CI run, plus deterministic unit tests for request schemas and replay mutations. This is an **engineering smoke**, not a statistically powered model benchmark.
- Halt on any root-path leakage to proposer, world-readable secret, wrong UID, missing test command, missing command exit check, incomplete recorder, socket mispermission, or lack of honest success.
- No retries to force a favorable hidden task. Failures remain visible in CI. If suite reveals a defect, append a scoped amendment/fix and preserve the failed run.

## Security limits

**CAN demonstrate:** Linux per-file discretionary permissions and Linux Unix-socket peer-UID checks under one measured CI configuration; bounded JSON interface; post-hoc deterministic replay and real positive/negative controls.

**CANNOT demonstrate:** strong sandbox isolation from arbitrary malicious code, host root compromise, Linux/kernel exploits, network egress confinement, ptrace/container escape prevention, CPU or memory exhaustion resistance, invisible side channels, full process/environment confidentiality, equivalent Android/Termux behavior, human authorization or world truth.

**No real model is invoked, no credentials are exposed, and no outside target is attacked.** This is a tightly bounded first step toward the EXP003-C1 blocker, not closure of that blocker.
