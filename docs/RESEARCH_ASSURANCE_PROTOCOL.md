## Expected behavioral checks, preregistered

- **A0 Positive:** intact archived baseline, exact claims, and real EXP003-P0 independent verifier all pass, with a bounded `ARCHIVE_CONSISTENT_ONLY` label; archive/source correctness does not imply independent physical-world truth.
- **A1 Byte mutation:** one changed evidence byte fails pinned SHA256 or immutable Git blob SHA1.
- **A2 Resealed mutation:** rewriting a registry JSON `sha256` to agree with a modified file still fails separately pinned historical Git-object ID and/or frozen code pin.
- **A3 Missing/deleted:** removing a registered original evidence, protocol, or report fails. Added replacement or supersession file does not erase the original.
- **A4 Modified protocol/source:** historical frozen protocol, historical runner, or historical verifier changed after the pilot fails file-identity check.
- **A5 Claim arithmetic:** changed 12/12 counts, probe totals 35/27/24, 36 policy/seed rows, or aggregate 86 probes fails against independently re-computed original records.
- **A6 Inference laundering:** trying to treat post-hoc probe-efficiency as confirmatory or any of the simulation as actual LLM performance fails explicit claim classification checks.
- **A7 Ledger drift:** tampering identity of claim, its evidence SHA or bound original source revision fails; claims may be *superseded through a new record*, not overwritten.
- **A8 Input hardening:** duplicate JSON keys, nonfinite numbers, malformed file paths and symlinked archive files cannot silently verify.
- **A9 No always-deny vacuity:** clean archive + ledger must pass A0. Simulated Sovereign Veritas input may reach ALLOW under explicitly synthetically-authorized, healthy, complete conditions, but production bridge **never creates those conditions**.
- **A10 SV negative controls:** actual commit-pinned SV Gate refuses missing external authorization even with consistent evidence; when synthetic authorization is on, missing methodology review causes DEFER; altered verification status FAIL causes REFUSE. The proposed action and capability must be matched.

Tests must not mutate tracked originals. Use temporary copies, changed in-memory bytes and injected pure functions. CI should run with `contents: read` and full-SHA pinned actions. A failed or skipped test is never reported as PASS.

## Verification-layer semantics

1. **BYTE_MATCH:** exact approved SHA256 / Git object bytes match an original file; no authorship or freshness.
2. **INTERNAL_CONSISTENT:** independent deterministic verifier reconstructs algorithm and outcomes; not real truth or methodological sufficiency.
3. **PROTOCOL_SCOPE:** recorded scope and post-hoc labels remain accurate; not an external scientific replication.
4. **REVIEW_REQUIRED:** eligible for a human to inspect; not APPROVED by the research system.
5. **AUTHORIZED_TO_PUBLISH / DEPLOY:** external *authenticated* human approval tied to exact candidate, revisions, evaluator, requested action. **Not implemented as an automatic outcome in RA-001.**

**Crucial:** The actual Sovereign Veritas Gate cannot itself authenticate runtime/metadata truth; it operates on supplied values. Its record may be entirely consistently rewritten. Its package verifier cannot observe the external-world effect. RA-001 is about making false promotions *detectable within a bounded record set*, not proving truth or safety.

## Open constraints

- GitHub `main` protection/rulesets require an authenticated settings action unavailable through current GitHub tool. Until a responsible owner configures it, a sufficiently privileged party can rewrite both code and manifest.
- Independent review/signature verification or trusted GitHub approval retrieval is not implemented here; hence no real `ALLOW` authorization claim.
- Main lacks a currently reviewed LICENSE; copying SV MIT code would require due notice, and is **not necessary**. RA-001 references SV at a pinned SHA and runs an external checkout test.
- `--pilot` is not an OS sandbox; EXP003-P0 arbitrary subprocess leakage risks remain open. Do not run untrusted proposers through RA-001.
- Research results already observed in the historical EXP003-P0 run remain **exploratory**; this registration covers only *new integrity engineering*.

## Exit criteria

A fresh clone can run one standard-library command to validate the original historical archive and associated claim ledger; a CI run demonstrates A0–A10 outcomes, including a genuine positive control and at least one failure for every stated guard. Ruleset installation and a second human's approval are **external owner tasks**. No experimental superiority claim is being sought.
